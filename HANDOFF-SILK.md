# SILK — Intel swipe performance (handoff notes)

## What was causing the choppiness (measured)
Profiled with Chrome traces and Long Animation Frame attribution: 390×844 iPhone viewport, CPU throttled 4×, 50 swipes (fast and slow, both directions), all 24 scenes and all 9 colour regions.
1. **Layout thrashing on every scroll event (main cause).**
   - A leftover `index.html` scroll listener ran `querySelectorAll` and read `clientHeight` on every scroll event, then wrote a counter. That forced a full style/layout pass each time.
   - The Intel stream's own handler did the same through `setIndex`.
   - Together: ~5.3 s of forced style/layout in 50 swipes.
2. **Heavy work at the halfway point of the drag.** When the slide crossed 50 %, `setIndex` ran mid-gesture and:
   - toggled classes on all ~37 slides (re-styling every scene);
   - mounted a new scene (`innerHTML`) and destroyed an old one (GC spikes);
   - drew a 150-particle canvas burst every frame on the main thread;
   - forced reflows (`void el.offsetWidth`) to restart animations;
   - started a full-scene `blur(8px) brightness()` filter animation.
3. **Main-thread scene animations.** Some loops animated `top`, `left`, `background-position`, `box-shadow`, SVG `fill` or `stroke-dashoffset`. Any one of them keeps the main thread painting every frame, including the top-bar sweep line and the NEW-badge shine.
4. **Whole-scene CSS filters.**
   - Every scene had a live `hue-rotate() saturate() brightness()` filter over all its running animations; on iOS that can take the scene off the GPU fast path.
   - Full-screen `mix-blend-mode: screen` overlays and `backdrop-filter` blurs over animated content added extra passes.
5. **Smaller items.**
   - The Atlas reconstruction hook observed the whole page, so it ran on every Intel scene mount and every title-decode frame.
   - Sound-scene timing queried animations (forcing style) every 110 ms, even mid-swipe.
   - Tilt parallax variables were written on the whole stream shell.

## What changed
- **Movement:** the browser's own scroller moves the slides.
  - It runs on the compositor thread, 1:1 with the finger.
  - Velocity flicks, rubber-banding at both ends and 120 Hz on ProMotion come from the system (iOS Safari limits JS animation to about 60 Hz).
  - `scroll-snap-stop: always` gives one slide per flick, like native pagers.
- **Per-frame JS while swiping:** one `scrollTop` read, then transform/opacity writes on two isolated layers:
  - the region veil (colours change only when the pair of regions changes);
  - the velocity-linked light streaks.
  - The canvas burst became a CSS starburst driven by finger velocity.
- **Settle:** index changes, scene mounting, sounds and the title decode wait until the slide has settled.
  - Settle means `scrollend`, or 130 ms of no scrolling with the finger up and the slide aligned.
  - Only the two slides that change are touched. No forced reflows.
- **Pre-warm and teardown:**
  - ±2 scenes are kept ready, built in idle time.
  - Teardown happens in idle time. There's a hard cap of 7 live scenes (normally 5); scenes at ±3 are released in idle time.
- **Lighter render while dragging:** the incoming scene stays paused until it settles, so only one scene animates during a drag. It then resumes with a transform-only arrival (no blur).
- **Transform/opacity only:** every scene loop now uses only transform/opacity, except the loader and the one-off rank badge pop. Converted:
  - dossier scan, tracker ladder, specimen scan line, nightwatch orb path, vault glow, hearing seats (now HTML dots);
  - gas-giant bands, dust, binary plasma (particles along the curve), megastructure panels, lava cracks;
  - top-bar sweep, NEW/SOTD shine.
- **No scene filters:** region colours for the 9 original scenes are baked into `intel-tint.css`.
  - It's generated by `tools/scene-tint.py` using the exact sRGB matrices CSS uses (pixel-exact in Chrome).
  - NEW HORIZONS scenes get pre-adjusted light colours (`--nxa/b/c`).
  - The per-slide ±6° hue jitter was dropped.
- **Blur and blend removed** from the stream top bar, rail and end card (denser glass instead), and from the region overlay.
- **Other fixes:**
  - The Atlas reconstruction hook now watches only the Atlas.
  - Sound-scene timing pauses mid-swipe.
  - Tilt variables are written on the visible slide only.
  - Keyboard navigation follows the pending target while gliding.

## Before → after (throttled iPhone-size test, 50 swipes, same conditions)
| Phase | rAF frame avg (before → after) | rAF worst | App main-thread work per frame, avg / p95 |
|---|---|---|---|
| Drag | 90.1 → 40.9 ms | 283 → 183 ms | 33.0 / 66.7 → 21.9 / 44.3 ms |
| Release | 147.2 → 32.1 ms | 467 → 217 ms | 67.9 / 157.7 → 20.3 / 50.5 ms |
| Settle | 63.9 → 37.0 ms | 283 → 333 ms | 28.3 / 65.7 → 19.7 / 43.9 ms |
| Idle on a scene | 18.9 → 16.7 ms (p95 33.4 → 16.7) | | |

- Frames delivered during release went from 188 to 680. Forced style/layout went from 5.3 s to under 0.4 s.
- The test browser renders on a software GPU with a 4× slowed CPU, so absolute numbers stay above budget there; the relative change is what the test can show.
- Memory over 50 swipes:
  - JS heap 4.3 → 4.4 MB.
  - Live scenes 4 → 6 (5 + end card).
  - Scene nodes 143 → 169, bounded.
